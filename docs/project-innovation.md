# 项目介绍、竞争力与创新点

## 1. 项目概述

**项目名称：** 溯源剧本工作台  
**项目方向：** AI 小说转剧本工具  
**项目定位：** 可信、可控、可追溯的多章节小说改编工作台

很多小说作者希望借助 AI 快速获得剧本初稿，但普通生成工具通常只返回一份看似完整的文本。作者很难判断：

- AI 的改编依据来自原文哪里；
- 关键剧情是否在改编中被遗漏；
- 人物、地点和对白归属是否正确；
- AI 是否擅自增加或改变了剧情；
- 作者编辑后的结果是否仍然符合交付格式。

本项目不只解决“生成剧本”，还围绕上述问题建立了完整可信改编闭环：

> 导入不少于 3 章小说，使用七牛 AI 生成结构化剧本，同时保留原文证据、事件覆盖关系和质量门禁，最终输出可编辑、可验证、可继续加工的 YAML 剧本。

项目公开仓库：<https://github.com/YingJinyan/ai-novel-to-script>  
Demo 视频：<https://www.bilibili.com/video/BV1D1EW6eEDs/>

## 2. 目标用户与使用场景

### 2.1 目标用户

- 希望把小说改编成短剧、影视剧或舞台剧初稿的作者；
- 需要快速评估小说影视化可能性的内容编辑；
- 需要结构化剧本数据的分镜、配音或视频制作工具开发者；
- 希望审查 AI 改编依据和剧情完整度的评审人员。

### 2.2 核心使用场景

1. 作者导入或粘贴不少于 3 章小说。
2. 系统检查章节结构、空章、重复标题和输入问题。
3. 作者选择七牛模型与改编详略。
4. 七牛 AI 提取人物、地点和事件，并生成场次、动作、对白与转场。
5. 系统恢复真实原文证据并执行质量门禁。
6. 作者在工作台审阅剧本、故事要素、事件覆盖和证据。
7. 作者编辑 YAML 后重新校验，下载通过门禁的剧本与验证包。

## 3. 与普通 AI 小说转剧本工具的差异

| 对比维度 | 常见一键生成工具 | 溯源剧本工作台 |
| --- | --- | --- |
| 主要目标 | 快速生成一份剧本文本 | 生成可审查、可验证、可交付的结构化剧本 |
| 输入检查 | 通常直接提交给模型 | 先检查章节数、空章、重复标题和字符限制 |
| 输出结构 | 连续文本或私有格式 | 公开、可执行的 YAML Schema |
| 原文依据 | 通常不可见 | 每个事件保存真实摘录、字符位置与章节哈希 |
| 剧情遗漏 | 依靠作者通读发现 | 使用事件覆盖矩阵逐项检查 |
| AI 错误处理 | 失败重试或直接展示 | 自动修复一次，仍不合格则给出具体阻断原因 |
| 作者修改 | 修改后状态不明确 | 编辑 YAML 后重新执行完整质量门禁 |
| 生成来源 | 容易混淆 AI 与规则结果 | 明确记录提供商、模型与生成模式 |
| 无 API 或断网 | 无法使用 | 可使用明确标注的可靠兜底模式 |
| 后续加工 | 依赖人工重新整理 | YAML 可继续用于分镜、配音和其他工具 |

本项目不与端到端视频生成平台比拼功能数量，而是专注把“小说转结构化剧本”这一关键中间环节做得透明、稳定和可复核。

## 4. 核心竞争力

### 4.1 从“一键生成”升级为“可信改编”

普通 AI 工具的结果往往是黑盒。本项目把改编过程拆分为：

```text
章节解析
→ 确定性原文证据单元
→ 七牛 AI 完整剧本化
→ 证据恢复与结构修复
→ Schema / 引用 / 证据 / 覆盖质量门禁
→ 作者审阅与交付
```

AI 负责理解语义和创作剧本，系统负责保护证据、结构与交付规则。两者职责分离，既保留 AI 的创作能力，也降低模型幻觉直接进入交付稿的风险。

### 4.2 面向作者的完整审阅工作台

工作台不是只展示最终 YAML，而是提供五种互相关联的审阅视图：

- **场次与证据：** 阅读动作、对白、说话人、来源摘录和改编动作；
- **故事要素：** 检查人物、别名、目标、地点和故事前提；
- **事件覆盖：** 检查每个来源事件进入了哪些剧本场次；
- **交付检查：** 查看覆盖率、溯源率、场次数要求和门禁问题；
- **原始 YAML：** 编辑后重新执行后端校验。

这使作者能够理解 AI 做了什么，而不是只能接受或放弃整份结果。

### 4.3 开放的结构化中间产物

项目没有把输出锁定在网页中，而是定义并公开了剧本 YAML Schema：

- [Schema 设计说明与设计原因](yaml-schema.md)
- [机器可执行 JSON Schema](../schema/screenplay.schema.json)
- [完整有效示例](../examples/screenplay.example.yaml)

Schema 将项目信息、改编控制、来源章节、故事圣经、叙事事件、场次和证据链分层管理。作者可以继续编辑，其他工具也能继续解析。

### 4.4 真实七牛 AI 接入与多模型选择

项目通过七牛官方 OpenAI 兼容接口完成真实 AI 调用，并从 `/v1/models` 动态读取当前账号可用模型。用户可以在网页中选择模型，不需要修改代码。

系统还对模型选择提供产品引导：

- 推荐适合结构化文本改编的模型；
- 标记可能较慢的推理模型；
- 避免把视觉模型误用于纯文本小说；
- 对超时、连接失败、非 JSON 输出和结构缺失返回真实错误。

项目提供真实七牛调用验收脚本。只有模型来源、人物地点提取、事件覆盖、剧本节拍和质量门禁全部满足要求，才会显示成功；不会把可靠兜底结果改成 AI 标签冒充成功。

### 4.5 可复现和可交付

项目为普通用户和评委提供：

- 一键启动与停止脚本；
- 七牛密钥隐藏输入和 Windows DPAPI 加密保存；
- 真实七牛调用验收工具；
- 零基础本地部署教程；
- 完整测试、依赖审计与密钥扫描；
- 独立验证包和可下载 Schema。

评委不仅能观看 Demo，也可以根据文档在本地复现整个流程。

## 5. 主要创新点

### 创新一：确定性证据恢复协议

AI 不直接填写原文字符位置和章节哈希。系统先把来源小说拆成带稳定 ID 的证据单元，AI 只能选择证据 ID；生成后由系统恢复真实摘录、字符起止位置与章节哈希。

这样可以避免模型伪造证据位置，并允许系统逐字验证：

```text
来源事件证据 == 原文章节[start_char:end_char]
```

价值：让 AI 改编结果具备可验证的原文依据。

### 创新二：小说事件与剧本场次的双向覆盖矩阵

系统把小说关键情节建模为独立叙事事件，再让每个场次声明来源事件：

```text
小说事件 → 剧本场次
剧本场次 → 小说事件
```

系统可以据此发现：

- 关键事件遗漏；
- 必保事件遗漏；
- 某个场次承载过多事件；
- 某个章节没有进入剧本；
- 场次引用不存在的事件。

价值：把“剧情有没有漏”从主观阅读问题变成可检查的结构问题。

### 创新三：多层质量门禁

系统不会因为模型返回了 JSON 就宣布成功，而是依次检查：

1. YAML Schema 是否合法；
2. 人物、地点、章节、事件引用是否存在；
3. 原文证据与字符位置是否准确；
4. 关键事件与必保事件是否全部覆盖；
5. 是否违反作者禁止新增剧情的要求；
6. 场次数是否符合作者选择的详略范围；
7. 中文小说是否被错误改编为英文。

不合格结果不会提供为“已通过剧本”，而会返回具体场次、人物、地点、剧情或结构字段的阻断原因。

价值：防止结构不完整、证据错误或语言错误的结果被误标为可交付。

### 创新四：AI 自动修复与确定性容错结合

模型输出不稳定时，系统不是简单放宽所有规则：

- 对缺失结构和语言错误，向同一模型反馈具体问题并自动修复一次；
- 对人物、地点的唯一轻微名称变体，进行确定性关联；
- 对无歧义的新人物或地点，登记到故事要素并提示作者复核；
- 对可能对应多个实体的歧义称谓，继续阻断；
- 对同章节漏映射事件，在安全范围内恢复关联并提示复核。

价值：减少“名称必须逐字一致”造成的无效失败，同时保留高风险错误的严格检查。

### 创新五：作者控制与生成结果联动

作者可以选择精炼、均衡或详细的改编详略。该选择不是只写入提示词，而是作为真实结构约束参与自动修复和质量报告。

系统同时支持：

- 忠实度；
- 改编重点；
- 必保事件；
- 是否允许新增事件；
- 禁止修改项；
- 可接受场次数范围。

价值：让作者的改编要求成为机器可检查的规则，而不是容易被模型忽略的自然语言愿望。

### 创新六：剧本 YAML 与独立验证包分离

剧本 YAML 保持适合作者阅读和继续编辑；验证包额外包含：

- 剧本对象；
- 来源章节正文侧车；
- 当前质量报告；
- 作者复核提示；
- 验证包版本。

价值：剧本可以单独交付，验证包可以在需要时用于独立复核证据链和交付状态。

## 6. 已完成的产品功能

### 6.1 输入与生成

- 导入或粘贴 3–100 章小说；
- 识别中文、英文与 Markdown 章节标题；
- 检查空章、重复标题、重复章节号、控制字符和字符限制；
- 七牛 AI 完整剧本化；
- 可靠兜底生成；
- 七牛可用模型动态读取与选择；

- 地点与地点描述；

- 对白说话人和表演提示；
- 来源章节、来源事件、原文摘录与改编动作。

### 6.3 审阅与交付

- 场次与证据审阅；
- 故事要素审阅；
- 事件覆盖矩阵；
- 质量门禁与问题定位；

### 6.4 工程与安全

- FastAPI 后端与 React + TypeScript 前端；
- 结构化 API 错误；
- 一键启动和停止 Demo；
- API Key 不进入前端；
- Windows DPAPI 加密保存本机七牛配置；
- Git 密钥扫描；
- 自动测试、生产构建和依赖审计；
- 零基础本地部署教程与 Demo 脚本。

## 10. 产品边界与未来规划

本项目不会声称 AI 文案能够完全替代作者判断。系统可以保证结构、引用、证据和覆盖关系，但人物动机、对白质量和影视表达仍需作者复核。

当前版本聚焦“可信小说转剧本”核心闭环，没有为了功能数量加入不稳定的视频生成或复杂协作功能。

未来可以在现有开放 YAML Schema 基础上扩展：

1. 可视化拖拽场次编辑和局部重新生成；
2. Fountain、FDX 和 PDF 剧本格式导出；
3. 多模型生成结果对比；
4. 角色关系、道具与时间线一致性检查；
5. 长篇小说分批改编与跨章节记忆；
6. 从场次继续生成分镜、配音和拍摄计划；
7. 作者修改与 AI 生成内容的版本差异审阅。

## 11. 总结

溯源剧本工作台的核心竞争力不是单纯“让 AI 写得更多”，而是：

> 让作者知道 AI 为什么这样改、是否漏掉剧情、结果能否交付，并保留继续编辑和继续生产的空间。

项目通过真实七牛 AI、开放 YAML Schema、确定性证据恢复、事件覆盖矩阵、质量门禁和独立验证包，将小说转剧本从一次不可解释的生成请求，升级为可控制、可验证、可追溯的创作流程。
