# AI 小说转剧本工具竞品调研

> 调研日期：2026-06-05  
> 调研方法：基于各产品官网、官方文档和官方 GitHub 仓库的公开信息进行案头研究，尚未完成全部产品的付费功能实测。文中的“机会判断”属于基于公开信息的产品推断。

## 1. 调研目标

本项目需要把不少于 3 个章节的小说文本转换为结构化 YAML 剧本。竞品调研重点回答以下问题：

1. 市面上的类似产品解决了哪些创作环节？
2. 它们如何处理长文本、人物一致性、剧本结构和后续编辑？
3. 哪些能力适合本项目借鉴？
4. 本项目应通过什么差异化设计获得更高的作品完整度与创新性？

## 2. 市场分类

目前类似产品大致分为四类：

| 类别 | 主要目标 | 代表产品 | 与本项目的关系 |
| --- | --- | --- | --- |
| 小说转短剧或漫剧平台 | 从小说快速生成剧本、分镜、素材甚至视频 | 剧云、奇漫AI、剧火AI、ArcReel | 直接竞品，偏向端到端内容生产 |
| AI 编剧工具 | 辅助构思、生成场景、分析剧本和协作 | NolanAI、Prescene | 直接或相邻竞品，偏向专业编剧流程 |
| AI 长篇写作工具 | 管理设定、角色和长篇上下文 | Sudowrite | 可借鉴长文本一致性设计 |
| 专业剧本与分镜工具 | 标准剧本编辑、排版、协作和分镜 | Final Draft、Boords | 可借鉴专业格式和人机协作体验 |

## 3. 代表产品分析

### 3.1 剧云

**公开定位与能力**

- 面向短剧、漫剧等内容生产。
- 官网公开功能包括剧本创作、AI 剧本评估、分镜设计和素材制作。
- 强调从创意到成片的一站式工作流。

**值得借鉴**

- 将创作拆成剧本、分镜、素材等阶段，用户容易理解当前进度。
- 剧本评估可以帮助用户发现冲突不足、节奏问题等质量风险。

**公开信息下的机会判断**

- 产品覆盖链条较长，本项目可以把“小说改编为结构化剧本”这一环节做得更透明、更可验证。
- 可把质量检查结果直接定位到具体场次和原文章节，而不只给出总体评分。

来源：[剧云官网](https://www.jucloud.com/)

### 3.2 奇漫AI

**公开定位与能力**

- 面向短视频、短剧和漫剧创作。
- 支持上传小说后自动生成剧本与分镜，并继续生成角色、场景、配音和视频。
- 强调人物一致性和端到端生成效率。

**值得借鉴**

- 上传小说后自动推进工作流，降低用户操作门槛。
- 人物一致性是小说改编场景中的关键产品卖点。

**公开信息下的机会判断**

- 本项目不需要与其竞争视频生成能力，可以专注于高质量、可编辑的中间产物。
- YAML 输出可作为开放格式，便于继续接入分镜、配音和视频工具。

来源：[奇漫AI官网](https://qimanai.com/)

### 3.3 剧火AI

**公开定位与能力**

- 面向 AI 影视和短剧创作。
- 官网介绍了上传小说、智能分析、生成剧本和分镜，以及进一步生成视频的流程。
- 强调角色、场景和道具的一致性。

**值得借鉴**

- 从小说分析开始，而不是直接生成最终内容。
- 将角色、场景和道具作为可复用资产管理。

**公开信息下的机会判断**

- 可以在本项目 Schema 中为角色、地点、道具分配稳定 ID，保证跨场景引用一致。
- 增加“一致性检查报告”，明确展示人物名称、时间线、地点和道具冲突。

来源：[剧火AI官网](https://www.juhuoshuzhi.com/)

### 3.4 ArcReel

**公开定位与能力**

- 开源 AI 视频生成平台，覆盖小说分析、剧本生成、分镜和视频合成。
- 官方仓库将长文本转视频拆分为独立工作阶段，并提供可本地部署的完整工程。

**值得借鉴**

- 开源项目的模块化流水线便于理解和复现。
- 将长文本分析、剧本、分镜和视频拆开，减少单次生成任务的复杂度。

**公开信息下的机会判断**

- 本项目应提供清晰的流水线状态和中间结果，而不是把 AI 调用封装成不可观察的黑盒。
- 可以将每阶段输入、输出和错误记录下来，方便重试和演示。

来源：[ArcReel 官方网站](https://arc-reel.com/zh/)、[ArcReel 官方 GitHub 仓库](https://github.com/ArcReel/ArcReel)

### 3.5 NolanAI

**公开定位与能力**

- AI 辅助编剧平台，提供 AI Co-Pilot、标准剧本编辑、角色设计和剧本分析等能力。
- 强调从构思到制作准备的协作流程。

**值得借鉴**

- AI 是编剧助手，不应直接覆盖作者的最终决定。
- 在专业剧本格式基础上提供生成和分析能力。

**公开信息下的机会判断**

- 本项目应允许作者在生成前确认角色表、故事梗概和改编设置。
- 生成后应支持逐场编辑和局部重新生成，而不是只能整体重做。

来源：[NolanAI 官网](https://www.nolanai.app/)

### 3.6 Prescene

**公开定位与能力**

- 面向影视创作者和团队的剧本分析平台。
- 支持导入常见剧本格式，进行故事分析、角色分析、覆盖报告和协作。
- 官网强调支持 PDF、FDX、Fountain 等专业剧本格式。

**值得借鉴**

- 剧本输出不仅要能阅读，还应支持后续分析和生产流程。
- 结构化数据可用于生成角色、地点和场次统计。

**公开信息下的机会判断**

- YAML Schema 应具备清晰、稳定的字段定义，后续可扩展导出到 Fountain 等格式。
- 可以基于结构化数据自动生成“场次统计”和“角色出场统计”，增强演示效果。

来源：[Prescene 官网](https://prescene.com/)

### 3.7 Sudowrite

**公开定位与能力**

- 面向小说作者的 AI 长篇写作工具。
- Story Bible 用于管理世界观、人物、故事概要和章节计划，帮助生成内容保持上下文一致。

**值得借鉴**

- 长篇内容不能只依赖单次提示词，需要先形成全局故事资料。
- 角色、世界观和情节规划应该成为独立的中间结果。

**公开信息下的机会判断**

- 对不少于 3 章的小说，应先生成“故事圣经”，再按场次生成剧本。
- 用户可以先修正人物或故事理解，再开始剧本生成，降低后续整体返工成本。

来源：[Sudowrite Story Bible 文档](https://docs.sudowrite.com/using-sudowrite/1ow1qkGqof9rtcyGnrWUBS/what-is-story-bible/jmWepHcQdJetNrE991fjJC)

### 3.8 Final Draft

**公开定位与能力**

- 专业剧本写作与排版软件。
- 提供行业标准格式、Beat Board、Story Map、修订管理和协作能力。

**值得借鉴**

- 场景标题、动作、人物、对白等剧本元素必须有明确类型。
- 故事节拍和场次关系需要可视化，而不仅是连续文本。

**公开信息下的机会判断**

- YAML Schema 应将场景标题、动作、对白和转场设计为不同结构，而不是混成字符串。
- 后续界面可以同时提供“场次列表”和“YAML 预览”两种视图。

来源：[Final Draft 官网](https://www.finaldraft.com/)

### 3.9 Boords

**公开定位与能力**

- 面向分镜和视频前期制作。
- 支持从文本或提示生成脚本和分镜，并允许团队编辑、协作和导出。

**值得借鉴**

- 从剧本到分镜需要稳定的场次和镜头级数据。
- 清晰的中间结构能让后续视觉创作工具继续使用。

**公开信息下的机会判断**

- 本项目的首版 Schema 应聚焦“剧本场次级”，同时预留可选的镜头扩展字段。
- 不应在首版投入完整视频生成，否则会分散题目要求中的核心质量。

来源：[Boords AI Script Generator](https://boords.com/ai-script-generator)

## 5. 本项目的产品机会

### 5.1 定位

本项目不是“一键生成短剧视频”的平台，而是小说作者与后续制作工具之间的**可信改编工作台**：

> 将多章节小说转换为可编辑、可解释、可校验、可继续加工的结构化剧本。

### 5.2 建议的差异化能力

1. **公开且可执行的 YAML Schema**
   - 字段设计、必填规则和设计原因全部公开。
   - 生成后自动校验，错误可以定位到具体字段。

2. **原文溯源**
   - 每个场次记录来源章节和原文证据片段。
   - 作者可以判断 AI 是否误解、遗漏或过度改编。

3. **先理解、再改编**
   - 先生成故事圣经、人物表、时间线和关键冲突。
   - 作者确认后再生成剧本，降低长文本改编失控风险。

4. **一致性质量报告**
   - 检查角色名称、关系、地点、时间线和未闭合情节。
   - 对每个问题给出严重程度和相关场次。

5. **人机协作与局部重生成**
   - 用户可以锁定满意的场次，仅重新生成选中内容。
   - 记录作者修改与 AI 生成的版本，避免整体覆盖。

6. **面向后续工具的开放中间格式**
   - 首版保证 YAML 导出质量。
   - 后续可扩展 Fountain、分镜、配音和视频工具适配器。

## 6. 首版功能边界

为了保证实训营作品完整度，首版建议聚焦以下闭环：

### 必须完成

- 导入或粘贴不少于 3 章的小说文本。
- 自动拆分章节并校验输入。
- 生成人物、地点、故事梗概和时间线。
- 用户确认改编设置。
- 生成结构化 YAML 剧本。
- 根据 YAML Schema 自动校验。
- 展示场次、对白、动作和来源章节。
- 支持编辑、局部重新生成和 YAML 下载。
- 展示一致性检查与基础统计。

### 暂不投入

- 完整短剧视频生成。
- 复杂多人实时协作。
- 专业影视预算和拍摄排期。
- 大量第三方剧本格式适配。

这些能力与长期方向有关，但不应影响首版核心链路的稳定性和演示质量。

## 7. 建议的演示表达

Demo 应围绕“传统 AI 一次生成不可控，本项目过程透明且结果可用”展开：

1. 导入一篇不少于 3 章的示例小说。
2. 展示系统识别出的章节、人物和时间线。
3. 修改一个错误的人物理解，再确认生成。
4. 展示分阶段进度和生成的剧本场次。
5. 点击某一场，查看其来源章节和原文证据。
6. 故意修改出一个非法字段，展示 Schema 校验错误。
7. 修正后下载 YAML，并展示一致性报告和角色出场统计。

## 8. 调研结论

市场已经证明 AI 能够辅助小说分析、剧本生成、分镜和视频生产，但公开产品大多强调生成速度或端到端成片。对本项目而言，最有价值的方向不是增加更多生成环节，而是提高小说改编结果的**可控性、可信度和互操作性**。

因此，项目后续设计应围绕三个核心词展开：

- **可解释**：每个场次能追溯到原文章节和改编决策。
- **可校验**：输出严格遵循公开 YAML Schema。
- **可编辑**：作者可以确认中间结果并局部调整，而不是被动接受一次性生成。
