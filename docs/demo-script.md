# Demo 视频脚本

建议时长：5–6 分钟。录制前关闭无关窗口和通知，浏览器缩放保持 100%。

## 录制前准备

在只保存于本机的 PowerShell 窗口中设置七牛密钥，然后执行：

```powershell
cd D:\job\ai_novel_to_script
.\scripts\verify-qiniu.ps1 -Model deepseek-v3
.\scripts\start-demo.ps1
```

必须从设置密钥的同一个窗口启动 Demo，后端才能读取密钥。只有验收脚本显示 `PASSED` 时，视频才能声明并展示真实七牛线上调用；否则按下文的离线备用路径录制。

## 0:00–0:30 项目定位

口播：

> 很多工具只负责生成，但作者还需要知道改编依据、是否遗漏、结果是否可信。溯源剧本工作台让小说改编结果可控制、可验证、可追溯。

展示：

- 首页完整界面。
- 顶部“离线规则模式（不调用 AI）”标签。
- 三步流程：输入检查、本地生成、溯源审阅。

## 0:30–1:30 导入与输入检查

操作：

1. 展示预置三章小说。
2. 点击“解析并检查”。
3. 展示章节数、字符数、章节标题和输入问题。

口播重点：

- 硬性要求是至少 3 章。
- 系统不会把空章或不合格输入静默送去生成。

## 1:30–3:30 可信生成与审阅

操作：

1. 点击“生成结构化剧本”。
2. 切换不同场次。
3. 展示来源原文摘录、来源事件、来源章节与改编动作。
4. 打开事件覆盖矩阵。
5. 打开质量门禁，展示覆盖率、来源追溯率和通过状态。

口播重点：

- 离线模式不调用 AI，不伪造无法证明的人物和具体地点。
- 每个场次都能回到真实原文证据。
- 覆盖矩阵用于发现遗漏，质量门禁用于阻止不可信结果通过。

## 3:30–4:40 YAML 编辑、阻断与验证包

操作：

1. 打开“原始 YAML”。
2. 删除 `project` 字段或制造一个明显错误。
3. 展示质量门禁变为“待校验”，点击“重新校验 YAML”。
4. 展示门禁阻断与具体问题。
5. 撤销错误并重新校验，展示恢复通过。
6. 点击“下载剧本 YAML”和“下载验证包”。

口播重点：

- 剧本 YAML 符合项目定义的 Schema。
- 作者修改后必须重新校验，未校验草稿不会被误标为通过。
- 验证包额外包含原文侧车数据，可独立复核证据链。

## 4:40–5:30 七牛 AI 与工程质量

真实验收通过时展示：

- 解析三章小说后，展示从七牛 `/v1/models` 读取的模型分类与选择。
- 选择已经验收成功的模型，点击“使用七牛 AI 润色”。
- 展示 AI 润色结果仍保留来源证据、质量门禁与作者复核警告。
- GitHub PR 列表和 Actions 测试结果。

口播：

> 这是一次真实七牛线上调用，但 AI 只能在确定性骨架内润色。它不能修改来源 ID、证据位置或哈希，动作文本必须保留来源证据，最终仍需通过质量门禁并由作者复核。仓库不包含任何真实密钥。

真实验收失败时展示：

- 未配置或不可用时七牛 AI 按钮明确禁用，或展示真实结构化错误。
- 使用离线规则模式完整演示核心流程。
- `docs/ai-provider.md` 的可信边界与真实验收工具。

失败时口播：

> 七牛接口、模型发现与质量门禁已经实现，但本次线上模型未通过受限输出验收，因此演示使用明确标注的不调用 AI 的离线规则模式，不用离线结果冒充 AI 成功。

## 录制检查

- 画面中不出现 API Key、账号密码、GitHub token 或代理配置。
- 至少展示一次真实解析、真实生成、真实证据和质量门禁。
- 不使用固定截图冒充实时运行。
- 视频结尾展示仓库地址和 README 快速启动方式。
- 录制结束后运行 `.\scripts\stop-demo.ps1`。
