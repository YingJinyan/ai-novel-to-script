# 七牛 AI 接入与可信边界

## 当前实现

项目将七牛 AI 作为可选提供商，调用官方 OpenAI 兼容接口：

- 默认地址：`https://api.qnaigc.com/v1/chat/completions`
- 鉴权：`Authorization: Bearer <API Key>`
- 输出格式：`response_format: {"type": "json_object"}`
- 官方参考：
  - [AI 大模型推理 API](https://developer.qiniu.com/aitokenapi/12882/ai-inference-api)
  - [支持的模型列表](https://developer.qiniu.com/aitokenapi/12884/ai-model-list)

配置环境变量：

```powershell
$env:QINIU_AI_API_KEY="你的 API Key"
py -3.10 -m uvicorn backend.main:app --reload
```

密钥只由后端读取。系统通过官方 `/v1/models` 接口读取当前账号可用模型，前端只接收模型 ID 列表，并允许用户选择本次生成使用的模型。可选环境变量 `QINIU_AI_MODEL` 用于设置默认模型。状态与模型接口都不会返回密钥。

Windows 本机可运行一次 `.\scripts\configure-qiniu.ps1 -Model deepseek-v3`。该脚本使用当前 Windows 用户的 DPAPI 加密密钥并保存到 Git 忽略的 `.local` 目录；`start-demo.ps1` 与 `verify-qiniu.ps1` 会自动读取。此配置只适合本机开发，不应复制到部署服务器。

慢模型可按需提高超时时间和最大输出长度：

```powershell
$env:QINIU_AI_TIMEOUT_SECONDS="240"
$env:QINIU_AI_MAX_TOKENS="14000"
```

客户端兼容纯 JSON、Markdown JSON 代码块和带简短说明的 JSON，并会在结构化响应无法解析时自动重试一次。超时不会伪装成成功。

如果模型返回了可解析 JSON，但遗漏人物字段、事件覆盖或场次引用，系统会把具体校验路径反馈给同一模型自动修复一次。自动修复后仍不合格时，接口会返回具体缺失项，不会降级为兜底结果冒充 AI 成功。

场次地点名称与地点表仅存在修饰词、标点或唯一相似差异时，系统会确定性关联，不再触发第二次 AI 调用。场次使用了地点表之外的新地点时，系统会登记为 AI 推断地点并附加作者复核警告。人物引用、来源事件和证据 ID 等高风险错误仍会严格拒绝或进入结构修复。

`deepseek-v3.1` 与 `deepseek/deepseek-v3.1-terminus` 在当前完整剧本化任务中可能响应较慢并发生生成期间连接中断，因此界面将其归入慢模型，不再作为默认推荐。演示优先使用 `deepseek-v3` 或 `qwen3-max`。

## 为什么采用“AI 完整剧本化 + 确定性证据恢复”

系统先将每章原文拆成带稳定 ID 的证据单元，再让模型完成完整剧本化改编：

- 提取原文明示的人物、别名、地点与目标；
- 每章提取一个或多个关键事件，并选择对应证据 ID；
- 根据事件和地点变化拆分场次；
- 生成动作、对白、旁白和转场。

模型不能自行填写原文字符位置或章节哈希。系统根据模型选择的证据 ID 恢复真实摘录、位置和哈希，并验证每章事件覆盖、场次事件映射与 Schema。剧本文案允许对原文进行可表演改写，因此系统同时保留作者语义复核警告。

这种设计不能自动证明 AI 文案绝无语义新增，因此每次 AI 改编都会附加 `ai_semantic_review_required` 警告，要求作者复核。

场次中的地点或人物称谓如果只是已有实体的唯一轻微名称变体，系统会自动关联。场次中首次出现且无歧义的新地点或人物会登记为 AI 推断实体，并提示作者复核；可能对应多个既有实体的歧义称谓仍会阻断，避免错误归属对白。

为避免“事件编号已覆盖但剧本正文没有真正演出来”，提示词要求每个来源事件在动作或对白中明确呈现，并优先按地点、时间和冲突阶段拆场。系统还会补齐节拍文字中明确出现却被模型漏列的出场人物；一个场次承载多个事件但节拍明显不足时，会给出带剧情摘要的压缩复核提示。

作者可以在生成前选择改编详略：精炼（3-5 场）、均衡（5-9 场）或详细（8-15 场）。该范围会作为真实结构约束参与自动修复，而不是只显示为模型可忽略的软提示；YAML 中的 `adaptation_control.target_scene_count` 记录所选范围的目标中值。

## 失败策略

- 未配置密钥或模型：返回 `503 qiniu_provider_not_configured`。
- 上游连接、超时或 HTTP 错误：返回结构化错误，不自动伪装成本地 AI 成功。
- 输出不是合法 JSON 或缺少场次：拒绝结果。
- 改编结果未通过质量门禁：返回完整质量报告，不向用户提供“通过”结果。
- 无密钥或断网演示：使用明确标注的可靠兜底模式，不冒充 AI 结果。

## 验证状态

已完成模拟 HTTP 契约测试、异常响应测试、完整改编输出测试与质量门禁测试。

仓库不包含真实七牛密钥。配置自己的合法密钥后，在设置密钥的同一个 PowerShell 窗口中运行：

```powershell
.\scripts\verify-qiniu.ps1
```

验收脚本会从七牛 `/v1/models` 核对模型，自动选择当前可用的已配置或推荐文本模型，真实执行一次三章小说完整剧本化改编。除核对七牛标签与模型外，它还要求结果提取人物和具体地点、覆盖全部章节事件、产生多节拍场次，并与可靠兜底骨架存在实质差异。需要指定模型时可追加 `-Model 模型ID`。脚本只打印非敏感摘要，不打印密钥或生成正文。只有脚本显示 `PASSED` 后，才能声明已完成真实七牛线上调用。
